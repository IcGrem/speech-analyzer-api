# Описание работы системы Speech Analyzer


### Архитектура и основной пайплайн обработки данных

Система представляет собой многоуровневый конвейер (pipeline), автоматизирующий сбор, предобработку и глубокий ML-анализ речевых данных. Основной процесс разделен на четыре ключевых этапа.

---

#### 1. Сбор данных (Data Acquisition)
Процесс инициируется **планировщиком** (`SchedulerService`), работающим в фоновом режиме.
*   **Механизм:** Каждый час планировщик вызывает метод `download_records` сервиса `VocaAPIService`.
*   **Источник:** Внешний API сервиса Voca.tech.
*   **Действия:**
    *   Выполняется запрос списка записей за указанный период (обычно предыдущий час).
    *   Реализован **Rate Limiting** (не более 30 запросов в минуту / 1 запрос в 2 секунды) для предотвращения блокировок.
    *   Аудиофайлы (`.wav`) и метаданные (`.json`) сохраняются локально в папку `speech_data/`.
    *   В базе данных создаются записи в таблице `audio_data`, а также регистрируются новые сотрудники (`Employee`), если они отсутствуют.

#### 2. Предобработка и консолидация (Audio Processing)
На этом этапе разрозненные аудиозаписи объединяются в единые блоки для последующего пакетного анализа.
*   **Механизм:** Выполняется через `AudioDataProcessor` (обычно по запросу к эндпоинту `/process-previous-day`).
*   **Действия:**
    *   Система группирует все необработанные записи (`is_processed=False`) по сотрудникам за предыдущие сутки.
    *   С помощью библиотеки `pydub` (ffmpeg) происходит **склейка (concatenation)** всех аудиофайлов сотрудника в один файл формата `{employee_id}_{date}_full.wav`.
    *   При склейке выполняется нормализация параметров аудио (Sample Rate, канальность).
    *   Результат сохраняется в `full_speech_data/`, а в БД создается запись в таблице `audio_data_for_analysis`, сигнализирующая о готовности данных к ML-анализу.

#### 3. ML-анализ (ML Pipeline)
Ядро системы, реализованное в модуле `ml_service.py` и папке `app/ml`. Процесс разделен на три стадии:

*   **1: VAD Segmentation (`AudioAnalyzer`)**
    *   Используется модель **Voice Activity Detection (VAD)** (библиотека `pyannote.audio`) для удаления пауз и нарезки дневного аудио на смысловые «чанки» (потенциальные диалоги).
*   **2: Diarization & ASR (`TextExtractor`)**
    *   **Диаризация:** Определение спикеров (Speaker 0, Speaker 1) внутри каждого чанка.
    *   **ASR (Speech-to-Text):** Транскрибация речи каждого спикера с помощью предобученных моделей HuggingFace (Transformers).
    *   Результатом является текстовый файл транскрипции с разметкой ролей.
*   **3: LLM Analysis & Scoring (`LLMAnalyzer`)**
    *   Текст транскрипции отправляется в **LLM** (OpenAI-совместимый API).
    *   **Разбиение:** LLM выделяет границы конкретных диалогов внутри чанка.
    *   **Типизация:** Определение типа диалога (например, `m2c` - менеджер-клиент или `m2m`).
    *   **Скоринг:** Для диалогов типа `m2c` LLM выставляет баллы (от 1 до 5) по 9 критериям: приветствие, полнота ответа, тон, эмпатия, грамотность речи и др.
    *   **Сохранение:** Итоговые данные (текст диалога, оценки, метаданные) записываются в таблицу `Dialog`.

#### 4. Пост-обработка и выдача данных (Post-processing & API)
Подготовка данных для отображения в интерфейсе.
*   **Подсветка (Highlighting):** Сервис `DialogTextHighlighter` анализирует сохраненные тексты диалогов, сопоставляет их с загруженными словарями фраз (используя NLP-библиотеку `natasha` для лемматизации) и внедряет HTML-теги `<span>` с цветами соответствующих словарей.
*   **Словарная привязка:** `DialogDictionaryPopulator` обновляет связи в таблице `dialog_dictionary`, позволяя фильтровать диалоги на фронтенде по наличию конкретных категорий фраз (например, «Конфликт», «Доп. продажи»).
*   **API эндпоинты:** Набор методов в `dialogs.py` обеспечивает пагинацию, фильтрацию по сотрудникам/датам/оценкам и генерацию данных для графиков (метрики эффективности сотрудников и организации).

### Технологический стек
*   **Backend:** FastAPI (Python 3.10+), SQLAlchemy (Async).
*   **ML:** Pyannote.audio (VAD/Diarization), Transformers (ASR), OpenAI API (LLM).
*   **NLP:** Natasha (лемматизация и морфология для поиска фраз).
*   **Audio:** Pydub (FFmpeg).
*   **Logging:** Loguru.
